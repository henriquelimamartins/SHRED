## Known risks

- Stale sessions: a device left open (e.g. the phone since yesterday) overwrites newer progress from another device on its next save, because every save is a full overwrite. Fixed in slice 3.4 (D81, D105), merged (PR #19). Until every open tab has loaded the new code, an old tab (pre-3.4) can still overwrite: it keeps the `syncRev` it read, so the new code cannot tell its write apart. After merge, reload the app on every device.
- Slice 3.4 limits (by design, D105): changes are never merged between devices; the losing side's change is kept only in that device's backups (restore UI comes in 3.8). The cloud is now re-read each time the app becomes visible (1 Firestore read) and each save costs 1 read + 1 write; well within the Spark free quota for one user.
- Sync: cloud overwrites local on login, and local-only fields are lost; writes can happen before the read finishes (fixed in Phase 3, D81). Covered by `current behaviour` tests in 1.2.
- On the first load of a new day, the app writes the cloud state straight back (daily reset) without any user action (found in 1.2). Fixed in slice 3.3 (D103), merged.
- Extra streak day (found in 1.4): if any DAILY block was ticked yesterday, opening the app today logged today in the streak before anything was practised. Fixed in slice 3.6 (D33, D108), merged (PR #22). Extra days already in the owner's data stay (D33: no rewrite of past data); they cannot be told apart from real days.
- Time zone (found in 1.4): the weekday came from the device clock, but "today" (streak, calendar, daily reset, item dates) from UTC. Fixed in slice 3.7 (D33, D109), merged (PR #23). Dates stored before the fix stay as they are (D33); in Lisbon they only differ for ticks made between 00:00 and 01:00 in summer.
- IMPROV gate locks are not enforced (found in 1.5): Library's Expression Track lets exercises of locked gates be marked, and un-marking an exercise of a passed gate does not lock it again. Covered by `current behaviour` tests. To be settled when IMPROV is rebuilt (Phase 7, D50).
- DOJO gives 100 XP for reading a Codex module (found in 1.5), which contradicts D40 (reading never creates progress). DOJO is replaced by THEORY in Phase 6 (D12); its stored data must still be kept. Covered by a `current behaviour` test. Until then its content sits in the THEORY destination unchanged (D114).
- ~~SETUP note text is wrong (found in 1.5)~~ fixed in 4.8b (D138): the note names the chosen gauge, tuning, guitar and scale. SETUP also still offers D Standard, Drop C, C Standard and DADFAE, beyond D63 (Standard and Drop D). Text-only fix; part of I01 (`IDEAS.md`); owner to decide the phase.
- Reset Everything wiped streak, calendar, SETUP and unknown fields. Fixed in slice 3.5 (D83, D106), merged (PR #20).
- Firestore Rules protect each account's document, but cannot stop the app itself from overwriting good data with stale data; that is what the Phase 3 sync safeguards fix.
- GitHub Pages deploys the whole repository, so the test files are publicly served too. They contain nothing sensitive (D84); excluding them from the deploy is a possible later slice.
- Content Security Policy (2.6, D98): any new outside source (Firebase SDK upgrade, new fonts, analytics, embeds) must be added to the policy in the same PR, or it will be blocked. Inline `style` attributes are still allowed (`'unsafe-inline'` for styles only) until the design overhaul (Phase 4, slice 4.9 since D125); since 4.1 only the two progress-bar widths remain inline. A `<meta>` policy cannot set `frame-ancestors` (clickjacking protection); GitHub Pages cannot send headers, so that stays open (low risk: no sensitive one-click actions).
- App icons (`favicon.png`, `apple-touch-icon.png`, `icon-192/512.png`) still use the old red `#ff3b30`, and `manifest.json` has white `background_color` / `theme_color` (seen when the app is installed on the phone). Left out of 4.1 (D118 point 6); a small later slice if the owner wants them in the new palette.
